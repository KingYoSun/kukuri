### 再利用の規則

- 再利用 = 内容 fingerprint と scan 構成 fingerprint がともに一致 かつ verdict が fail-closed
  （scan failure / provider unavailable / unscanned / hold）でない。fingerprint 欠落（旧行）は再 scan。
- 再利用時は provider を呼ばず artifact を作らない。非 allow の再利用で著者があれば
  `risk_signal_subject_authors` への関連付けだけ行う（共有 blob の 2 人目の著者）。
- 撤回・tombstone・送信防止・本文解決は再利用判定より前（順序不変）。

### risk signal の集約

- 鍵 `(issuer_node_id, target, target_id, category, basis)` の活性行（cleared 以外 かつ
  `expires_at` 無し）が 1 件。再 scan は severity / confidence / visibility を更新し
  id / persisted_at / appeal_status を据え置く。
- 失効していない cleared 行があれば新規行を作らない（INVAR-4）。cn-cli の再発行は旧行に
  `expires_at` を刻んでから呼ぶため、cleared 済み行があっても訂正版を作れる。appeal 審査の
  再発行（旧行 cleared → 新行 raw INSERT）も部分 UNIQUE と両立。
- 検知メタデータ編集で category を変えた結果が別の活性行と衝突する場合は unique violation で
  取引が巻き戻る（INV-9。`edit_detection_category_collision_is_rejected_without_partial_write`）。
