$auditMetadata = cargo metadata --no-deps --format-version 1 | ConvertFrom-Json
$auditMetadata.packages | Where-Object {

rg --files crates/core crates/store crates/transport crates/docs-sync crates/blob-service -g '*.rs'
rg --files crates -g '*.rs' | Where-Object { $_ -match '^crates[\\/]cn-[^\\/]+[\\/]' }

## C-CN-1: 現状・全caller・凍結境界

### 観測した構造

- `IngestPipeline`は`docs_sync` / `safety` / `entries` / `projection` / `blob_service` / `metrics`の6依存を持つ。
- `resolve_body_text`はsame-pass envelope mapを使い、BlobTextについて署名、ID、author、payload metadata、size、hash、UTF-8、文字数を確認する。blobは`fetch_blob_ephemeral`を使う。InlineTextはそのまま返す。
- `media_scan_targets` → `resolve_media_manifest`はDocsSyncから署名済みmanifestを読み、kind / authorを検証する。attachments、manifest items、thumbnailをhashで先勝ち重複排除する。
- 上記3methodはすべてpipelineの`&self`に到達できる。source検証だけを変更する場合にも、provider scan・metrics・index mutationを持つ大きなownerを扱う必要がある。
- #745はBlobTextの内容を正しく検索に出すための修正で、source検証と`blob_service`依存をpipelineへ追加した。続く#746は同fileのscan metrics分類、#774はwithdrawal/preventionの判定を同fileへ追加しており、sourceとpublish policyが独立して変化していることを履歴で確認できる。
- これが不具合の原因だったと断定していない。今回達成するのは、その別責務の変更を互いの副作用へアクセスできない境界へ分けることである。
