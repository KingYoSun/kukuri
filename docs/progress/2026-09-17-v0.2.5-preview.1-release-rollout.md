## sourceと検証

- 準備PR [#1081](https://github.com/kukuri-app/kukuri/pull/1081) は17 checks成功後にマージ。linux-desktop-uiのDM状態保持テストが5秒timeoutで2回失敗し（差分はversion文字列のみ、ローカルでは8件成功）、3回目の再実行で成功。flakeは [#1086](https://github.com/kukuri-app/kukuri/issues/1086) で扱う。merge commitの差分がPR差分と同一であることを確認。

- `cargo xtask release-check v0.2.5-preview.1` / `v0.2.5-preview.2` / `v0.2.5-preview.3`、`git diff --check`、operator-config validation、Terraform fmt／validate成功。
- preview.1 sourceのmain Fast `35181393702` と preview.2 sourceの `35186992560` は、linux-cn-e2e の `replica_query_failure_keeps_new_posts_out_of_surfaces_until_recovery` で失敗（索引0件、期待1件）。原因は #1080 の参照再確認中の replica query 一時障害で索引済み投稿が de-index される経路で、[#1090](https://github.com/kukuri-app/kukuri/issues/1090) として修正済み（preview.3 に含む）。

### moderation 構成の変更

- operator-config（非公開）: `safety.providers.general` を `openai-moderation`／`required: true`／`hosting: external` へ変更。OpenAI provider は general slot 専用のため `unknown_csam` slot を削除。`deploy` の VLM endpoint／model／応答形式を削除し、`deploy.moderation`（`https://api.openai.com/v1`、`omni-moderation-latest`、`config_version: "1"`、RPM 400／RPD 8000／TPM 8000／画像予約2048）を追加。known_csam は Project Arachnid Shield のまま。
- 法務文書: 外部送信文書に第三者への外部送信として OpenAI Moderation API が載り、self-host VLM の記載が消える。`external_transmission` と `moderation_policy` を version 2（施行日 2026-09-17）へ上げた。moderation-policy v2 は #1054 の文言反映を利用規約改訂（#1056）と同じ回にまとめる既定方針による。`policy_snapshot_revision` は `56e3a6ca…` から `391a5f54…` へ変わり、再同意は1回にまとまる。他の生成文書の差分はネットワーク図の送信先表記だけ。
- 非公開tfvarsは `cn-operator generate-tfvars` の出力に、既存の手動追記（operator_config_path、通知チャネル、期待topic）を保持して反映。差分は4 image refs、moderation、provider、VLM 3項目の空値化、`safety_general_action = ""` だけ。
- Secret Manager `kukuri-cn-vlm-api-key` に OpenAI のキーを version 2 として追加（version 1 はrollback用に有効のまま）。`latest` が運営者の設定値と一致することを値を出力せずに照合。VMからOpenAI Moderation APIへの到達と認証（HTTP 200）を、キーをコマンドラインに載せずに確認。
