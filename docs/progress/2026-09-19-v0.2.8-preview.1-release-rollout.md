## 現在の状態

- クライアント5本体（Windows NSIS、Linux AppImage／Deb、CLI x86_64／aarch64）を source `a9536dfd`（tag `v0.2.8-preview.2`）から公開した。Community Node の image 更新・VM 反映は含めない。
- 目的は v0.2.7-preview.1 以降の main の変更（URL パースと OGP プレビュー #1179、カスタムリアクション名の tooltip #1178、composer への画像の貼り付け #1177、画像 viewer のクリッピング修正 #1175 など）を配布し、あわせて Namespace へ移した release workflow（[#1180](https://github.com/kukuri-app/kukuri/issues/1180)）を実際の release で確認すること。実 release での確認はユーザー承認済み（2026-09-19）。
- 受入条件は v0.2.7-preview.1 と同じ: 同一sourceの5本体、3 updater entryの実署名・改変拒否、公開後取得照合。

## sourceと検証

- 版同期は区分Aの機械的保守（[#1182](https://github.com/kukuri-app/kukuri/pull/1182)）。workspace・Tauri・frontendを0.2.8へ同期。Cargo.lockは自前packagesのversionだけが変わり、外部依存と依存関係は不変。
- `cargo xtask release-check v0.2.8-preview.1`／`v0.2.8-preview.2`、`git diff --check` 成功。

## v0.2.8-preview.1（失敗、未公開）

- tag `v0.2.8-preview.1`（source `e720649d`）の公開 run [35415877964](https://github.com/kukuri-app/kukuri/actions/runs/35415877964) は、linux-verify が Namespace の Ubuntu 22.04 image に PowerShell が無いことで失敗した。publish 系は skipped で、Release は作成されていない。
- 修正（[#1183](https://github.com/kukuri-app/kukuri/pull/1183): PowerShell の導入、linux-verify の reusable workflow 化）の後、tag を上書きせず同じ 0.2.8 を `v0.2.8-preview.2` として公開した。tag `v0.2.8-preview.1` は Release の無い tag として残る。
