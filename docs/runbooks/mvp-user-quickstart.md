# MVP利用者向けクイックスタート

## 対象

- Builder Previewを試すデスクトップ利用者向け
- Windows NSIS、Linux x86_64 AppImage／Debを[v0.2.0-preview.2](https://github.com/KingYoSun/kukuri/releases/tag/v0.2.0-preview.2)で公開済み
- Linuxは[AppImage手順](linux-appimage-smoke.md)または[Debの導入・署名付き更新・削除手順](linux-deb.md)を参照。CLI x86_64／aarch64も同Releaseで配布し、[専用手順](linux-cli.md)を参照

## 3分で試す

1. [最新のGitHub Release](https://github.com/KingYoSun/kukuri/releases/latest)から自分の環境向けのWindowsインストーラーまたはLinux AppImage／Debを取得し、上記の形式別手順に従って起動する。
2. appの規約確認を終えたら「コミュニティノードとは？」を読み、「規約を確認する」で一覧先頭のノード（配布時の候補はkukuri.app）の規約へ進む。文書を確認して「同意する」を押すと、接続準備が始まる。「あとで」を選んだ場合も、見つけるまたはコミュニティノード設定から規約確認へ戻れる。保存済みの空一覧には候補を再追加しない。
3. 2番目のプロフィールカラムを開き、「プロフィールを編集」から表示名、ユーザー名、自己紹介、必要なら画像を設定する。
4. 先頭のタイムラインカラムへ戻り、最初から用意されたトピックのどれかを開く。
   - `kukuri:topic:general`（雑談・分類のない一般的な投稿）
   - `kukuri:topic:dev`（kukuri の開発・技術・改善案・バグ）
   - `kukuri:topic:test`（投稿・同期・画像・P2P 挙動などのお試し）
5. 公開投稿かスレッドへの返信を1件試す。添付できるのは画像と動画だけで、テキストやPDFなどのファイルは添付できない。非対応のファイルを選ぶと投稿作成の中に理由が表示される。
6. 同じトピック内でプライベートチャンネルを作るか参加する。入口はタイムラインカラム上部の「プライベートチャンネル」ボタン、または「コントロールセンター → 場所 → チャンネル作成・参加」。招待・共有リンクは、参加後にタイムラインカラム上部の「設定と共有」（またはコントロールセンターのチャンネル設定）から作成する。
7. 「見つける」「通知」「メッセージ」の各カラムを開き、主要機能の入口を確認する。同意後も検索が使えない場合は、表示された理由と「状態を再確認」または「コミュニティノード設定を開く」に従う。接続の手助けと検索機能の提供は別なので、検索非提供のノードでは別の検索提供ノードを選ぶ。
8. 設定でコミュニティノードの診断情報を確認し、フィードバックを送る。
9. 「設定 → リリース」で更新状態を確認し、診断レポートをコピーまたは書き出す。

## 確認するポイント

初回の規約画面では、上部の「言語 / Language」から日本語・English・简体中文を選べます。言語の切替だけでは同意しません。言語が未保存ならOSのUI言語を使い、保存済みの言語は次回起動でも優先します。通常画面では「コントロールセンター → 設定 → 表示と言語」の先頭で変更できます。日本語を選ぶと、同梱されている規約・プライバシーポリシーの日本語正文を読めます。

- トピックが主軸で、チャンネルはトピック内の共有範囲として理解できるか
- 初期5カラムからプロフィール設定、探索、通知、メッセージへ迷わず移動できるか
- コミュニティノードが投稿の保管先ではなく、初期接続・認証・接続支援を担うものとして見えるか
- 自動認証と必須同意の導線が前面に出過ぎず、初回利用の手間を減らせているか

## Linuxでソースから起動する

公開済みAppImageを使う場合は[AppImage手順](linux-appimage-smoke.md)を参照する。チェックサムと署名・公開元を確認してから実行し、追加Ubuntu／Debian・XWayland等の未確認条件を動作保証として扱わない。以下のソース実行は配布物がない場合にも使える。

```bash
cargo xtask doctor

cd apps/desktop
npx pnpm@10.16.1 install
npx pnpm@10.16.1 dev
```

起動後の確認ポイントはWindowsプレビューと同じです。

## フィードバック

- 「設定 → リリース」の診断レポートと一緒にGitHubへフィードバックを送る
- 診断レポートは秘密鍵、認証トークン、プライベートチャンネルの秘密情報、招待・共有トークン、DM本文、端末内データベースの保存先を既定で含まない
- 特に聞きたいのは次の 3 点です
  - トピック中心の使い方が最初に伝わったか
  - トピック内のチャンネルが自然に感じられたか
  - コミュニティノードの役割境界が理解しやすかったか

## 更新

- プレビューの更新確認は「設定 → リリース → 更新を確認」で行う。
- 更新が見つかったら「インストール」を押し、インストール完了後にアプリを再起動する。
- 更新後もアカウントを識別する鍵、プロフィール、フォロー関係、自分の投稿、端末内データベース、Irohのデータ、コミュニティノード設定、プライベートチャンネルの閲覧権限、通知一覧が残っていることを確認する。

## 端末バックアップと復元

- 「設定 → アカウント → 端末バックアップ」で、現在使用中の1アカウントを暗号化された1ファイルへ保存できる。複数アカウントはアカウントごとにファイルを作成する。
- 対象はアカウント鍵、端末内データベース、未同期データ、下書き、添付とローカル docs/blob、ワークスペース・テーマ・言語設定、Community Node 設定、プライベートチャンネルの秘密・招待情報である。
- 復元は公開鍵と内容をプレビューし、別領域で復号・整合性・外部接続を行わないDB migrationを検証してから切り替える。同じ公開鍵が存在する場合は明示確認が必要である。`Installing`／`Installed`中の停止は次回起動時に旧アカウントへrollbackし、`Committed`／`AwaitingConsent`では再同意待ちの新アカウントへfinish-forwardする。`Activated`後にcleanupが中断した場合も次回起動で完了する。
- 端末固有の iroh endpoint secret、Community Node の bearer token、OS通知権限、アプリ規約同意、年齢申告、Nodeポリシー同意、成人向け表示設定は移行しない。復元後に同意・申告・設定をやり直し、アプリ規約への再同意とactivationが完了するまでは復元したアカウントのruntime、network処理、復元したfrontend設定の適用を開始しない。
- バックアップには本人性と非公開データを復元できる秘密が含まれる。ファイルとパスフレーズは安全に保管する。復元しても旧端末やP2Pネットワーク上のコピーは削除されない。

## アカウント鍵だけの持ち出しと復元

- 「設定 → アカウント」で、アカウントを識別する鍵をパスフレーズ付きで暗号化してエクスポートできる。エクスポートした文字列とパスフレーズを安全な場所に分けて保管すれば、端末の故障・変更時にも同じアカウント(同じ公開鍵)を復元できる。
- エクスポートが漏えいすると第三者があなたになりすませる。パスフレーズを忘れた場合、運営者を含む誰にも復元できない。
- 別の端末では「設定 → アカウント → インポート」で公開鍵フィンガープリントを確認してからアカウントとして追加し、切り替えて利用を再開する。
- この機能が移行するのはアカウントを識別する鍵だけです。投稿の端末内データベース、設定、添付、プライベートチャンネルの閲覧権限などを含む端末移行には、上の端末バックアップを使う。

## データの安全性

- 「設定 → リリース」には、最新リリース、このクイックスタート、リリース手順書、第三者ライセンス表示、既定のコミュニティノードの開示情報へのリンクがある。
- ブラウザーで開くリンク: [リリース](https://github.com/KingYoSun/kukuri/releases/latest)、[利用規約](https://api.kukuri.app/terms)、[プライバシー](https://api.kukuri.app/privacy)、[外部送信](https://api.kukuri.app/external-transmission)、[通報方針](https://api.kukuri.app/abuse-policy)、[データ保持](https://api.kukuri.app/data-retention)。
- プレビュー更新の動作確認では、アカウントを識別する鍵、プロフィール、フォロー関係、自分の投稿、端末内データベース、Irohのデータ、コミュニティノード設定、プライベートチャンネルの閲覧権限、通知一覧が保持されることを確認する。
- アンインストールまたはリセットの前に、移行対象の全アカウントについて端末バックアップを作成し、別の安全な場所へ保管する。
