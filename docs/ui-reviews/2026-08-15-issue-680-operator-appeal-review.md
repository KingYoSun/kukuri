# 課題 #680 異議申し立て審査画面の確認記録

- 対象: 課題 #680 の実装ブランチ `codex/issue-680-operator-appeal-review`
- 画面見本: [異議申し立て審査一覧](assets/2026-08-15-issue-680/operator-appeal-review.png)
- 変更概要: コミュニティノード運営者が、同じリスク判定への匿名の異議申し立てを一つの審査対象として確認し、認容・棄却・検知情報の調整・訂正版の再発行を確認画面を経て実行できるようにした。
- 確認結果: 承認。審査対象、申立内容、信頼評価への影響、操作後の状態が一つの画面で分かり、保存済み文字列が無害化され、狭い画面でも操作欄が縦に並ぶことを確認した。
- 例外: なし。
- 検証: 管理画面の単体試験、通信契約試験、`Postgres` 結合試験、`cargo xtask desktop-ui-check`、画面見本による目視確認。

## 運営者の操作手順

1. `GCP IAP` と権限管理の内側にある管理画面を開く。
2. 「異議申し立て審査」で、リスク判定ごとにまとめられた申立件数と現在状態を確認する。
3. 判定情報と申立内容を読み、認容・棄却・検知情報の調整・訂正版の再発行のいずれかを選ぶ。
4. 確認画面で信頼評価と関連通報への影響を確認して適用する。
5. 完了表示と更新後の状態を確認する。確認後に別の操作が先に適用されていた場合は、最新状態を読み直して判断する。

## 対話設計の確認

- 一貫性: 既存の管理操作と同じ `preview`、`confirm`、`apply` の三段階を使う。
- 近道: 一覧内の対象から、判定情報と関連する全申立てをその場で確認できる。
- 分かりやすい反応: 参照専用、有効化不足、古い確認内容、適用完了をそれぞれ明示する。
- 操作の完結: 確認画面で変更内容と影響を示し、適用後は完了表示へ戻す。
- 誤操作の防止: `CSRF`、運営者識別子、機能の有効化、確認時点の版を適用時に再検証する。
- やり直しやすさ: 検知情報の調整と訂正版の再発行は審査中のまま残し、認容または棄却まで再確認できる。
- 運営者による制御: 自動判断を行わず、すべての状態変更を明示操作に限定する。
- 記憶負荷の軽減: 対象、判定根拠、申立内容、信頼評価への影響、操作欄を同じ審査枠にまとめる。
