# 課題 #667 コミュニティノード招待認証画面の確認記録

- 作業ブランチ: `codex/issue-667-community-node-invite-admission`
- 表示例: [招待コードが必要なノード](assets/2026-08-15-issue-667-community-node-invite-admission.png)
- 確認結果: 承認
- 例外: なし

## 確認した流れ

1. 招待コードが必要なノードでは、拒否理由と次の操作をノード設定内に表示する。
2. 招待コードを伏字入力し、対象ノードだけに保存して認証を再実行する。
3. 認証成功後は接続補助情報を取得し、保存済みの招待コードで再接続できる。
4. 無効、期限切れ、利用上限、失効では新しいコードの確認または取得を案内する。
5. 許可一覧外と利用禁止では招待コード入力を表示せず、ノード運営者への連絡を案内する。
6. 利用者または運営者の対応が必要な拒否では、自動再試行を行わない。

## 画面設計の確認

- 一貫性: 既存の入力欄、通知、ボタン、ノード単位の設定カードを再利用した。
- 操作の近道: 設定画面を離れず、コード入力から保存、認証まで一度の操作で完了できる。
- 状態の明示: 拒否理由、次の操作、保存済み状態、保存・認証中を入力欄の近くに表示する。
- 操作完了: 認証結果を同じノードの接続状態へ反映し、成功時は入力値を画面から消す。
- 誤操作の防止: 未保存ノード、空のコード、処理中は保存操作を無効にし、利用禁止時はコード入力を表示しない。
- 取り消しやすさ: 入力中の値は送信前に編集でき、ノード削除または設定全消去で保存値も削除する。
- 利用者の主導権: 拒否後は定期再試行せず、利用者の再入力または運営者対応を待つ。
- 記憶負担の軽減: 7 種類の拒否を日本語の理由と具体的な次の操作へ変換して表示する。

## 実表示で確認した点

- 招待コードが伏字で表示され、入力欄の焦点枠が明暗テーマで識別できる。
- 拒否理由と次の操作が入力欄の直前にまとまり、狭い幅でも横方向にはみ出さない。
- 招待コードは画面へ再表示せず、保存済みかどうかだけを案内する。

## 検証

- `Settings/CommunityNodePanel/InviteRequired` の実表示と画像を確認
- 部品試験で対象ノードへの伏字入力、送信後の入力消去、利用禁止時の入力非表示を確認
- 翻訳試験で 7 種類の拒否理由と次の操作に日本語文言があることを確認
- `cargo xtask desktop-ui-check` で画面一式を最終確認
