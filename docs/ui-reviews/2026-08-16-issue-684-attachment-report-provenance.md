# 課題 #684 添付通報の観測元確認記録

- 作業ブランチ: `codex/issue-684-attachment-provenance`
- 表示基準: [課題 #666 で承認済みの通報画面](assets/2026-08-14-issue-666/resolved-report-routing.png)
- 確認結果: 承認
- 見た目の変更: なし
- 例外: なし

## 確認した流れ

1. 観測元を持つ画像付き投稿から画像表示を開く。
2. 複数画像のうち表示中の添付から通報操作を開く。
3. 選択した添付のハッシュを対象識別子、`media` を対象種別として保持する。
4. 添付自身の正本を `blob` とし、親投稿から引き継いだ観測経路で最新のノード公開情報を取得する。
5. 観測経路と責任範囲が一致する候補だけを表示し、観測元がない場合は既定ノードへ代替しない。
6. ダイアログを閉じて投稿の通報操作を開くと、投稿の対象識別子と `author_docs` の正本へ戻る。

## 画面設計の確認

- 一貫性: 課題 #666 で承認済みの通報ダイアログと操作位置を変更していない。
- 操作の近道: 画像表示から離れず、表示中の添付を直接通報対象にできる。
- 状態の明示: 公開情報の取得中、失敗、候補なし、候補ありの既存表示を維持する。
- 操作完了: 送信結果と受付番号を既存ダイアログ内で示す。
- 誤操作の防止: 投稿用の観測元を添付へ使い回さず、選択したハッシュに結び付いた観測元だけを使う。
- 取り消しやすさ: 送信前はダイアログを閉じて画像表示または投稿へ戻れる。
- 利用者の主導権: 候補が複数ある場合の選択と送信確認を維持する。
- 記憶負担の軽減: 表示中の添付をそのまま対象にするため、利用者がハッシュや観測元を覚える必要がない。

## 検証

- 表示変換試験で添付ごとの `blob` 正本と観測経路を確認
- `PostCard` 部品試験で表示中の添付の観測元だけから公開情報を取得することを確認
- 再起動試験で投稿、プロフィール、添付の観測元復元を確認
- `community_node_report_routing` で投稿、プロフィール、添付の候補判定と送信を確認
- `cargo xtask desktop-ui-check` で既存画面に視覚差分がないことを最終確認
