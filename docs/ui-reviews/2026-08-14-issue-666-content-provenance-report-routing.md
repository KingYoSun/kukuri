# 課題 #666 観測元に基づく通報画面の確認記録

- 作業ブランチ: `codex/issue-666-content-provenance`
- 表示例: [観測元から解決した通報先](assets/2026-08-14-issue-666/resolved-report-routing.png)
- 確認結果: 承認
- 例外: なし

## 確認した流れ

1. 投稿、スレッド、しおり、著者詳細、添付表示から対象に合った通報操作を開く。
2. 端末内に記録した観測元だけから、最新のノード公開情報を取得する。
3. 対象の表示に関与し、かつ対象能力への責任を表明しているノードだけを候補として示す。
4. 投稿、プロフィール、添付の種別と識別子を保ったまま、選んだノードへ通報する。
5. 観測元がない場合、または公開情報を取得できない場合は、既定のノードへ送らず、端末内のミュート操作だけを案内する。
6. 通報者の連絡先は任意入力とし、未入力なら送信しない。

## 画面設計の確認

- 一貫性: 既存のダイアログ、通知、ボタン、色、余白の変数を再利用した。
- 操作の近道: 元の表示を離れずに通報先の確認から送信まで完了できる。
- 状態の明示: 通報先の確認中、確認失敗、送信中、送信成功を同じ画面で区別する。
- 操作完了: 受付番号を表示し、閉じる操作で元の表示へ戻れる。
- 誤操作の防止: 観測元と責任範囲が一致しない候補は表示せず、既定の送信先へ代替しない。
- 取り消しやすさ: 送信前はいつでも閉じられ、通報先がない場合は端末内のミュートを選べる。
- 利用者の主導権: 候補が複数ある場合は利用者が送信先を選ぶ。
- 記憶負担の軽減: 対象、送信先、関与した能力、受付方法、方針への導線を一画面にまとめた。

## 実表示で直した点

初回確認では、候補と入力欄が横方向につながって読みにくかった。候補をカード状の縦配置にし、選択状態、能力、受付方法、入力欄の区切りが分かるよう修正した。幅の狭い画面ではダイアログ内を縦に移動でき、横方向にはみ出さない。
