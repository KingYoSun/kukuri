# 課題 #669 リスク判定への異議申し立て画面の確認記録

- 送信前の表示例: [発行元と匿名性の確認](assets/2026-08-15-issue-669/appeal-before-submit-risk-judgment.png)
- 受付後の表示例: [受付番号とリスク判定識別子](assets/2026-08-15-issue-669/appeal-submitted-risk-judgment.png)
- 確認結果: 承認
- 例外: なし

## 確認した流れ

1. 投稿から開いた著者詳細、または自分自身の著者詳細で、コミュニティノードの情報を明示的に読み込む。
2. 評価根拠を展開し、リスク判定の発行元、分類、深刻度、確信度、公開範囲、異議申し立ての状態、評価への寄与を確認する。
3. 未申立てのリスク判定で「このリスク判定に異議を申し立てる」を選ぶ。
4. `issuer_node_id` と設定済みノードの `node_id` が一致し、`report_endpoint` がある場合だけ送信先として表示する。別ノードや連絡先だけの候補へは代替しない。
5. 発行元と匿名送信であることを確認し、必要なら再確認してほしい内容を入力して送信する。利用者の連絡先は入力欄も送信項目も持たない。
6. 応答の `disputed_risk_signal_id` が送信対象と一致した場合だけ受付完了を表示し、評価根拠を再取得する。
7. `Disputed` では再送操作を表示せず、審査中も評価への寄与が続くことを示す。`Cleared` では寄与から除外済みであることを示す。

## 画面設計の確認

- 一貫性: 既存の通報用ダイアログ、通知、ボタン、入力欄、色と余白の変数を再利用した。
- 操作の近道: 著者詳細を閉じずに、根拠確認から異議申し立て、状態再取得まで完了できる。
- 状態の明示: 送信先を発行元だけに限定し、匿名性、送信中、受付完了、受付不能、解決済みを操作箇所の近くへ表示する。
- 操作完了: 受付番号と受付対象のリスク判定識別子を表示し、閉じる操作で更新済みの根拠表示へ戻れる。
- 誤操作の防止: 発行元の照合に失敗した場合は送信ボタンを表示せず、応答識別子が一致しない場合も成功扱いにしない。
- 取り消しやすさ: 送信前はキャンセルまたは閉じる操作で元の表示へ戻れる。
- 利用者の主導権: 情報取得と異議申し立てはいずれも利用者の明示操作でのみ行う。
- 記憶負担の軽減: `Disputed` の間は寄与が続き、`Cleared` で除外される規則を各状態の近くへ常時表示する。

## 実表示で直した点

初回確認では、共用通報部品の宛先見出し、能力名、受付方法が英語表示のまま残り、見本には発行元以外の候補も含まれていた。異議申し立て表示では文言を平易な日本語へ統一し、発行元と一致する送信先一件だけを表示する見本へ修正した。幅420画素でも横方向にはみ出さず、送信ボタンまで縦方向に確認できることを確認した。
