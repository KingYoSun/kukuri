# 課題 #690 索引結果の通報文脈確認記録

- 作業ブランチ: `codex/issue-690-index-report-context`

- 確認結果: 承認
- 見た目の変更: なし
- 例外: なし

## 確認した流れ

1. ノードを選択し、検索・発見・おすすめのいずれかを実行する。
2. 応答を表示するとき、取得元ノード、取得操作、取得範囲を結果と一体で保持する。
3. ノード、取得操作、取得範囲を変更すると、以前の結果と通報対象を消し、進行中の古い応答も表示しない。
4. 結果から通報を開くと、結果を取得したノードの最新の `CommunityNodeManifest` を取得する。
5. 検索・発見では `community_index` と検索結果、おすすめでは `recommendation` とおすすめを通報画面に表示する。
6. 最新のノード公開情報を取得できない場合は候補を作らず、保存済み情報や別ノードへ代替しない。
7. 日本語画面では、認証、同意、未設定、一時停止、回数制限の既知エラーを日本語で表示する。

## 画面設計の確認

- 一貫性: 既存の索引画面、通知、通報画面、ボタンと入力欄をそのまま使う。
- 操作の近道: 結果から直接通報を開ける既存の操作数を増やさない。
- 状態の明示: 検索中、結果なし、エラー、通報先の確認中、確認失敗、候補ありを既存の表示で区別する。
- 操作完了: 通報受付後は既存の受付結果と受付番号を表示する。
- 誤操作の防止: 古い結果を現在選択中の別ノードへ送れず、古い応答も新しい文脈へ表示しない。
- 取り消しやすさ: 送信前は通報画面を閉じて結果へ戻れる。
- 利用者の主導権: ノード・取得操作・取得範囲の選択と通報送信は利用者の明示操作でのみ行う。
- 記憶負担の軽減: 取得元と取得操作を内部で保持するため、利用者が通報先を覚えて選び直す必要がない。

- 画面試験で、検索結果とおすすめの対象種別・能力・送信先表示を確認
