- 変更概要: 運営操作の確認・完了・拒否ページと異議申し立て審査の確認ページを、ダッシュボードと同じ共通 shell(`admin_shell.rs`: 色 token、余白、button 階層、focus-visible、header)に載せ替えた。header にダッシュボードへ戻る link と現在の段階(適用前の確認 / 操作完了 / 未適用)を示し、実行者・対象・変更前後・影響・取引境界を同じ比較枠で並べる。主操作(確認して適用 / ダッシュボードへ戻る)と副操作(取り消す)を button 階層で区別した。
- 確認結果: 承認。375px / 760px / 1280px × dark / light の全組み合わせで横スクロールが発生せず、Tab 移動で 戻る link → 確認して適用 → 取り消す の順に focus-visible(teal outline)が表示されることを確認した。ダッシュボード本体の見た目は従来どおり。
- 例外: 非 appeal 操作の確認ページでは「変更前」を DB から読まず「適用時に現在値を再取得します」と明示する(preview ハンドラに読み取りを追加しない。現在値の事前表示は別課題)。画面見本は描画関数の出力 HTML(listener が返すものと同一)をブラウザで撮影した。

## 運営者の操作手順

1. ダッシュボードで「変更内容を確認」を押す。
2. 確認ページの header で現在位置(コミュニティノード運営 › 適用前の確認)を見て、同じ管理面にいることを確かめる。
3. 比較枠で実行者・対象・変更前後・影響・取引境界を読み、「確認して適用」または「取り消す」を選ぶ。
4. 完了ページで操作記録の識別子と変更前後を確認し、「ダッシュボードへ戻る」で戻る。拒否された場合は理由と「状態と操作記録は変更されていません」を確認して戻る。

## 対話設計の確認

- 一貫性: ダッシュボードと同じ色 token・余白・角丸・button 階層を共有し、段階が変わっても同じ shell に留まる。
- 近道: header の link 1 つでダッシュボードへ戻れる。keyboard だけで 戻る → 適用 → 取り消す に到達できる。
- 分かりやすい反応: 段階(適用前の確認 / 操作完了 / 未適用)を header に明示し、完了ページで変更前後を等幅で示す。
- 操作の完結: 完了・拒否ページとも次の行動(ダッシュボードへ戻る)を主操作として示す。
- 誤操作の防止: 主操作と副操作の階層を分け、取引境界と再検証の方針を適用前に示す。
- やり直しやすさ: 「取り消す」で変更せずに戻れ、拒否時は状態が変更されていないことを明示する。
- 運営者による制御: 自動遷移や隠れた状態変更は無く、適用は明示操作に限る。
- 記憶負荷の軽減: 実行者・対象・変更前後・影響・取引境界を 1 つの比較枠に集め、画面間で覚え直す項目を減らす。
