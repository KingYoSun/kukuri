# 課題 #685 異議申し立て対象と解消済み表示の確認記録

- 作業ブランチ: `codex/issue-685-appeal-contract`
- 確認対象: `Core/AuthorDetailCard/CommunityNodeAdvisory`、`Core/AuthorDetailCard/CommunityNodeClearedPostAdvisory`
- 確認幅: 420画素
- 確認結果: 承認
- 例外: なし

## 確認した流れ

1. 著者詳細でコミュニティノードの情報を読み込み、評価根拠を展開する。
2. 利用者を対象とする根拠では、対象をプロフィールとして表示し、プロフィールの識別子を異議申し立てへ渡す。
3. 投稿を対象とする根拠では、対象を投稿として表示し、元の投稿識別子を異議申し立てへ渡す。
4. 対応していない対象種別はプロフィールへ置き換えず、申立て操作を表示しない。
5. 運営者が認容した投稿の根拠を再取得すると、「認容済み」と寄与ゼロを表示し、異議申し立て操作を表示しない。

## 画面設計の確認

- 一貫性: 課題 #669 で承認済みの根拠一覧と異議申し立て用ダイアログを維持した。
- 操作の近道: 根拠を展開した場所から、その根拠自身の対象へ異議を申し立てられる。
- 状態の明示: 対象種別、対象識別子、申立て状態、評価への寄与を同じ根拠内に表示する。
- 操作完了: 認容後の再取得では解消済みであることと寄与ゼロを確認できる。
- 誤操作の防止: 投稿対象をプロフィールとして送らず、未対応の対象を推測で置き換えない。
- 取り消しやすさ: 送信前は既存の閉じる操作で根拠一覧へ戻れる。
- 利用者の主導権: 送信対象と発行元を確認したうえで、利用者の明示操作でのみ送信する。
- 記憶負担の軽減: 元の対象種別と識別子を根拠に併記し、利用者が別画面の識別子を覚える必要をなくした。

## 検証

- `Vitest` で利用者対象をプロフィール、投稿対象を投稿として送信することを確認
- `Vitest` で解消済みの投稿根拠が認容済み・寄与ゼロで表示され、再送操作がないことを確認
- `cargo xtask ipc-types --check` で生成済み通信型の一致を確認
- `cargo xtask cn-test` で利用者の送信、運営者の認容、再取得後の解消済み表示用データを確認
- `cargo xtask desktop-ui-check` で部品見本、型検査、画面回帰を最終確認
